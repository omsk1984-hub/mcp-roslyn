## Что сделано

- **TFM**: все проекты уже были `net10.0` (src/tests/benchmarks/DocGen), фикстуры —
  `net10.0`, кроме намеренной `LegacyLib` (v4.6.2). Менять не потребовалось.
- **NuGet**: стабильные пакеты уже на актуальных версиях (`dotnet list package --outdated`);
  взяты: `BenchmarkDotNet 0.15.8 → 0.16.0-preview.2` (единственный актуальный),
  тестовый стек — миграция `xunit v2 (2.9.3) → xunit.v3 (4.0.2)` (решение пользователя).
- **Тестовый стек**: удалены VSTest-мосты (`Microsoft.NET.Test.Sdk`,
  `xunit.runner.visualstudio`, `coverlet.collector`) — они инертны для MTP-приложений
  на .NET 10; добавлен `Microsoft.Testing.Extensions.CodeCoverage 18.12.0` (MTP-native).
- **Собственный entry point** [`TestEntryPoint.cs`](../tests/RoslynCodeLens.Tests/TestEntryPoint.cs)
  + `XunitAutoGeneratedEntryPoint=false`: авто-entry-point xunit регистрирует
  MTP-расширения только на ветках `--server`/`--internal-msbuild-node`, поэтому
  `--coverage` не работал при прямом запуске exe. Свой entry point всегда маршрутизирует
  через `TestPlatformTestFramework.RunAsync(args, SelfRegisteredExtensions.AddSelfRegisteredExtensions)`.
- **Workflow тестов переведён на прямой запуск MTP-хоста** (решение пользователя):
  на .NET 10 SDK VSTest-таргет для MTP-приложений не поддерживается, а opt-in нового
  `dotnet test` через `global.json` в SDK 10.0.401 не найден (перепробовано множество
  кандидатов свойства — ни одно не меняло поведение; `sdk.version` в global.json читается,
  значит механизм global.json жив, но имя свойства test-runner не идентифицировано).
- Удалены `coverage.runsettings` (coverlet/VSTest-специфичен) и экспериментальный `global.json`.
- Обновлены правила/скиллы/доки на MTP-workflow: `01-test.md` (переписан),
  `00-worklog.md`, `03-roslyn.md`, `rules/01-general.md`, `rules/02-roslyn-codelens.md`,
  `skills/solid-plan-implementation`, `skills/edit-validation-protocol`,
  `plugins/.../SKILL.md`, `CLAUDE.md`, `README.md`, `README_ru.md`, `.github/workflows/ci.yml`.
- **Dockerfile**: `sdk:11.0 → 10.0` (выравнивание с TFM net10.0).

## Зачем

- Задача «перевести библиотеки на .NET 10» свелась к обновлению NuGet + тестового стека:
  TFM уже были net10.0.
- xunit v3 — MTP-native; на .NET 10 SDK `dotnet test` (VSTest) для таких приложений мёртв.
  Прямой запуск MTP-хоста — единственный рабочий путь, покрывающий и прогоны, и coverage.
- Coverage через MTP-расширение даёт тот же cobertura-отчёт для Codecov, что и coverlet.

## Риски / дальше

- `dotnet test` для этого решения нерабочен по дизайну SDK 10 — все прогоны (локально и в CI)
  идут через exe MTP-хоста. Любой новый агент/разработчик должен читать `01-test.md`.
- `Microsoft.Testing.Extensions.CodeCoverage` требует InstrumentationEngine (нативные DLL);
  на Linux CI (ubuntu-latest) поведение покрытия не проверялось локально — проверить при
  первом прогоне CI.
- Исторические `docs/plans/*`, `plans/*`, `worklog/*` содержат `dotnet test` как архивные
  упоминания — намеренно не переписывались (журнал не редактируется задним числом).
- Изменяющие MCP-инструменты (`rename_symbol`/`change_signature`/`apply_code_action`) в этой
  сессии не применялись; все правки — через `apply_diff`/`write_to_file`.
