# Правило: журнал изменений в `decision/` перед завершением (Code-режим)

Перед любым вызовом `attempt_completion` в режиме code — кратко зафиксировать
проделанную работу в каталоге [`decision/`](decision/README.md)
(`D:\work\MCP\mcp-roslyn\decision`). Это журнал решений агента: следующий агент
или человек должен понять, что и зачем было сделано, не перечитывая весь diff.

## Когда заполнять

- Любая задача, изменившая файлы в репозитории (код, конфиги, правила, документы).
- Диагностическая задача без правок — запись тоже желательна (раздел «Вывод»),
  если результат не тривиален.
- Исключение: чисто разговорный ответ без работы с файлами.

## Формат записи

Один файл на задачу/сессию, чтобы параллельные агенты не конфликтовали:

```
decision/YYYY-MM-DDTHH-mm-<короткий-slug>.md
```

- Дата и время — **UTC** (согласно `.roo/rules/01-general.md`), например
  `decision/2026-10-26T18-05-fix-report-writer.md`.
- Slug — 2–5 слов, kebab-case, по сути задачи.

Шаблон содержимого (кратко, без воды):

```markdown
# <Заголовок задачи>

- Дата (UTC): 2026-10-26T18:05Z
- Режим/агент: code

## Что сделано
- <1–5 пунктов: суть изменений и принятые решения>

## Зачем
- <мотивация, альтернативы которые отклонены — если были>

## Затронутые файлы
- `path/to/file1.cs` — <что изменено>
- `path/to/file2.md` — <что изменено>

## Проверка
- get_diagnostics: <ошибок/предупреждений>
- dotnet test: <результат, какие проекты>

## Риски / дальше
- <что осталось, на что обратить внимание>
```

## Правила заполнения

- Запись **краткая**: несколько строк на раздел; журнал, а не отчёт.
- Указывать реальные пути файлов относительно корня репозитория.
- Если в ходе задачи были правки через изменяющие MCP-инструменты
  (`rename_symbol` / `change_signature` / `apply_code_action`) — отметить это
  в «Что сделано» (они пишут на диск в обход подтверждений).
- Файлы в `decision/` не удалять и не переписывать задним числом — только
  добавлять новые записи.
- Пустая папка `decision/` не считается нарушением: при первой записи создать
  файл по шаблону выше.

## Порядок действий (чеклист перед attempt_completion)

1. Все правки внесены, `get_diagnostics` и тесты (если применимо) пройдены.
2. Создан файл `decision/<timestamp>-<slug>.md` по шаблону.
3. Только после этого — `attempt_completion`, упомянув путь к записи в результате.
