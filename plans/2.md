## 1. `get_code_actions` (с параметром `includeNested`)

**Полное описание:**  
Возвращает список доступных рефакторингов (code actions) в указанной позиции/диапазоне файла. Поддерживает вложенные действия (nested actions) для сложных рефакторингов типа Extract Method.

**Проблема (из кейса 1):**  
Агент 4–5 раз рассуждал вслух о том, есть ли у `ExtractMethodCodeRefactoringProvider` вложенные действия (`NestedActions`), не имея фактов. Каждый «Хм» — потерянный цикл рассуждения (~15 минут).

**Решение:**  
Один вызов `get_code_actions` с параметром `includeNested: true` на реальном файле с выделенным диапазоном показал бы точную структуру действий: есть вложенные или нет.

**Сигнатура использования агентом:**
```json
{
  "tool": "get_code_actions",
  "arguments": {
    "filePath": "D:\\work\\MCP\\mcp-roslyn\\src\\RoslynCodeLens\\Tools\\ApplyFixLogic.cs",
    "line": 55,
    "column": 1,
    "endLine": 64,
    "endColumn": 25,
    "includeNested": true
  }
}
```

**Ожидаемый результат:**
```json
{
  "actions": [
    {
      "title": "Извлечь метод",
      "equivalenceKey": "Extract_method",
      "nestedActions": [
        { "title": "EmitPrefix", "equivalenceKey": "Extract_method_EmitPrefix" }
      ]
    }
  ],
  "totalCount": 1
}
```

## 2. `get_code_actions` (возврат `equivalenceKey` вместе с `title`)

**Полное описание:**  
Тот же инструмент, но с явным возвратом поля `equivalenceKey` для каждого действия. Это позволяет агенту матчить действия по стабильному ключу, а не по локализованному заголовку.

**Проблема (из кейса 2):**  
Агент рассуждал о `CodeAction.Kind` (которого у refactoring-ов почти нет), прежде чем вспомнить про `EquivalenceKey`. На ru-RU сборке это привело бы к молчаливому провалу — `get_code_actions` возвращает «Извлечь метод», а код ищет «Extract method».

**Решение:**  
`get_code_actions` возвращает и `title`, и `equivalenceKey` одновременно. Один реальный вызов показал бы: `title = "Извлечь метод"`, `equivalenceKey = "Extract_method"`. Матчинг по второму полю стал бы очевидным сразу.

**Сигнатура использования агентом:**
```json
{
  "tool": "get_code_actions",
  "arguments": {
    "filePath": "D:\\work\\MCP\\mcp-roslyn\\src\\RoslynCodeLens\\Tools\\ApplyFixLogic.cs",
    "line": 55,
    "column": 1,
    "endLine": 64,
    "endColumn": 25
  }
}
```

**Ожидаемый результат:**
```json
{
  "actions": [
    {
      "title": "Извлечь метод",
      "equivalenceKey": "Extract_method",
      "isPreferred": false
    }
  ]
}
```

## 3. `get_type_overview` (для `TextLine`)

**Полное описание:**  
Возвращает краткую информацию о типе: свойства, методы, конструкторы. Используется для быстрого ознакомления с API без чтения всего исходника.

**Проблема (из кейса 3):**  
Агент написал `endLineObj.Length` для `TextLine`, не проверив доступные свойства. Компилятор поймал ошибку (`CS1061: "TextLine" не содержит определения "Length"`), но это стоило цикла build→error→fix.

**Решение:**  
Вызов `get_type_overview` для `Microsoft.CodeAnalysis.Text.TextLine` мгновенно показал бы свойства `Start`, `End`, `Span`, `SpanIncludingLineBreak` — и `Length` не появился бы в коде.

**Сигнатура использования агентом:**
```json
{
  "tool": "get_type_overview",
  "arguments": {
    "symbolName": "Microsoft.CodeAnalysis.Text.TextLine"
  }
}
```

**Ожидаемый результат:**
```json
{
  "typeName": "TextLine",
  "namespace": "Microsoft.CodeAnalysis.Text",
  "properties": [
    { "name": "Start", "type": "int" },
    { "name": "End", "type": "int" },
    { "name": "Span", "type": "TextSpan" },
    { "name": "SpanIncludingLineBreak", "type": "TextSpan" }
  ],
  "methods": [...]
}
```

## 4. `get_method_source` (для сигнатур методов)

**Полное описание:**  
Возвращает исходный код метода с точной сигнатурой (параметры, возвращаемый тип, модификаторы). Используется для понимания API без гадания.

**Проблема (из кейса 4):**  
Агент перепутал `SyntaxNode` и `SyntaxTree` при вызове `Document.WithSyntaxRoot()` / `compilation.ReplaceSyntaxTree()`. Компилятор ответил `CS1503: не удается преобразовать из "SyntaxNode" в "SyntaxTree"`.

**Решение:**  
Вызов `get_method_source` для `Document.WithSyntaxRoot()` показал бы точную сигнатуру: `public Document WithSyntaxRoot(SyntaxNode root)`. Ошибка не возникла бы.

**Сигнатура использования агентом:**
```json
{
  "tool": "get_method_source",
  "arguments": {
    "symbolName": "Microsoft.CodeAnalysis.Document.WithSyntaxRoot"
  }
}
```

**Ожидаемый результат:**
```json
{
  "methodName": "WithSyntaxRoot",
  "signature": "public Document WithSyntaxRoot(SyntaxNode root)",
  "parameters": [
    { "name": "root", "type": "SyntaxNode" }
  ],
  "returnType": "Document",
  "source": "..."
}
```

## 5. `find_references` (для поиска паттернов сборки тестов)

**Полное описание:**  
Находит все использования символа (переменной, метода, типа) в кодовой базе с фильтрацией по типу использования (read, write, invocation и т.д.).

**Проблема (из кейса 5):**  
Агент собирал `CSharpCompilation` в тестах без `MetadataReference` на `System.Runtime` / `typeof(object).Assembly`. Это базовая грабля Roslyn-тестов, но она повторялась. Тесты падали с `CS0518: Предопределенный тип "System.Object" не определен`.

**Решение:**  
Вызов `find_references` на `MetadataReference.CreateFromFile` по кодовой базе показал бы все существующие примеры сборки тестовых компиляций — и агент с первого раза скопировал бы рабочий шаблон.

**Сигнатура использования агентом:**
```json
{
  "tool": "find_references",
  "arguments": {
    "symbolName": "Microsoft.CodeAnalysis.MetadataReference.CreateFromFile",
    "kinds": ["invocation"]
  }
}
```

**Ожидаемый результат:**
```json
{
  "references": [
    {
      "filePath": "tests/RoslynCodeLens.Tests/ExceptionAnalyzerTests.cs",
      "line": 45,
      "code": "MetadataReference.CreateFromFile(typeof(object).Assembly.Location)"
    }
  ],
  "totalCount": 1
}
```

## 6. `get_code_fixes` (для диагностики `CS0246`)

**Полное описание:**  
Возвращает список доступных исправлений (code fixes) для указанной диагностики в позиции файла. Позволяет выбрать нужный фикс по `equivalenceKey` или `title`.

**Проблема (из кейса 6):**  
Агент запускал `dotnet test --filter Cs0246_Apply_FixesError` минимум 4 раза, пытаясь понять, почему `apply_fix` не добавляет `using`. Вместо того чтобы посмотреть, какие именно `CodeAction` возвращает `get_code_fixes` для `CS0246`.

**Решение:**  
Один вызов `get_code_fixes` на реальном `CS0246` с позицией показал бы список фиксов с их `EquivalenceKey`. Агент сразу увидел бы, что нужный фикс существует, и проверил бы, почему `ApplyFixLogic` его не находит.

**Сигнатура использования агентом:**
```json
{
  "tool": "get_code_fixes",
  "arguments": {
    "filePath": "tests/RoslynCodeLens.Tests/Fixtures/Cs0246Fixture.cs",
    "line": 10,
    "column": 5,
    "diagnosticId": "CS0246"
  }
}
```

**Ожидаемый результат:**
```json
{
  "fixes": [
    {
      "title": "using System.Collections.Generic;",
      "equivalenceKey": "AddUsing_System_Collections_Generic",
      "diagnosticId": "CS0246"
    },
    {
      "title": "Generate class 'List'",
      "equivalenceKey": "GenerateClass_List",
      "diagnosticId": "CS0246"
    }
  ],
  "totalCount": 2
}
```

## 7. `apply_code_action` (с параметром `preview: true`)

**Полное описание:**  
Применяет указанный рефакторинг (code action) к файлу. По умолчанию работает в режиме preview — возвращает список правок без записи на диск. Позволяет увидеть результат до применения.

**Проблема (из кейса 7):**  
Агент предположил, что Roslyn extract-method:
1. автоматически делает метод `private` (а он делает его с модификатором по умолчанию),
2. удаляет исходный код из тела (а он оставляет вызов нового метода).

Тесты падали: `Not found: "private void EmitPrefix()"`, `Found: "Console.WriteLine(a);"`.

**Решение:**  
Запуск `apply_code_action` в режиме `preview: true` на фикстуре показал бы точный результат правки до того, как агент начал бы писать тесты на ожидаемое поведение. Тесты писались бы по факту, а не по догадке.

**Сигнатура использования агентом:**
```json
{
  "tool": "apply_code_action",
  "arguments": {
    "filePath": "tests/RoslynCodeLens.Tests/Fixtures/ExtractMethodFixture.cs",
    "line": 10,
    "column": 5,
    "endLine": 15,
    "endColumn": 25,
    "actionTitle": "Извлечь метод",
    "preview": true
  }
}
```

**Ожидаемый результат:**
```json
{
  "edits": [
    {
      "filePath": "tests/RoslynCodeLens.Tests/Fixtures/ExtractMethodFixture.cs",
      "startLine": 10,
      "endLine": 15,
      "newText": "EmitPrefix();\n\nprivate void EmitPrefix()\n{\n    Console.WriteLine(a);\n}"
    }
  ],
  "conflicts": []
}
```

## 8. `find_references` / `get_symbol_context` / `search_symbols` (вместо `searchFiles` с regex)

**Полное описание:**  
- `find_references` — находит все использования символа с семантическим контекстом.
- `get_symbol_context` — возвращает полную информацию о символе (определение, все использования, связанные символы).
- `search_symbols` — нечёткий поиск символов по имени.

**Проблема (из кейса 8):**  
Агент использовал `searchFiles` с regex для поиска определений типов, делегатов, методов:
```
searchFiles regex: "PreviewOrApplyAsync"
searchFiles regex: "enum ToolErrorCode|record TextEdit|record RenameConflict"
```
Это находило совпадения в комментариях, строковых литералах, `using static`, не различало `read` и `write`.

**Решение:**  
- `find_references` на `PreviewOrApplyAsync` → все вызовы с контекстом, без шума.
- `get_symbol_context` на `CommitWrittenDocuments` → определение + все использования.
- `search_symbols` для нечёткого поиска по имени типа.

**Сигнатура использования агентом:**

**Вариант A: `find_references`**
```json
{
  "tool": "find_references",
  "arguments": {
    "symbolName": "RoslynCodeLens.SolutionChangeSafety.PreviewOrApplyAsync",
    "kinds": ["invocation"]
  }
}
```

**Вариант B: `get_symbol_context`**
```json
{
  "tool": "get_symbol_context",
  "arguments": {
    "symbolName": "RoslynCodeLens.CommitWrittenDocuments"
  }
}
```

**Вариант C: `search_symbols`**
```json
{
  "tool": "search_symbols",
  "arguments": {
    "query": "ToolErrorCode",
    "kind": "enum"
  }
}
```

**Ожидаемый результат (для `find_references`):**
```json
{
  "references": [
    {
      "filePath": "src/RoslynCodeLens/Tools/ApplyCodeActionLogic.cs",
      "line": 45,
      "kind": "invocation",
      "code": "await SolutionChangeSafety.PreviewOrApplyAsync(...)"
    }
  ],
  "totalCount": 4
}
```

### Запрет 1: Гадание об API Roslyn
Прежде чем рассуждать о внутренностях Roslyn-типов (`CodeAction`, `TextLine`, `SyntaxNode` и т. п.) — вызови `get_type_overview` или `get_symbol_context`.

Для идентификации code actions используй `equivalenceKey`, а не `title`. Заголовки локализованы и меняются в зависимости от культуры.
